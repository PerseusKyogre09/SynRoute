# Architecture

Synroute is a modular monolith. `core` owns task contracts and lifecycle transitions; `repository` discovers a canonical Git root and project hints; `workspace` creates detached worktrees and tracks both current-process and durable ownership; `sandbox` defines provider-independent execution types, authorization policy, and a Docker CLI provider; `verification` authorizes and runs explicit argv checks only through a configured sandbox; `storage` owns SQLite migrations and async repositories; `recovery` performs conservative restart inspection. `agent` remains an adapter boundary. The execution coordinator, Codex integration, Repo Memory, and API execution endpoints are not implemented.

## Phase 2 execution boundary

Verification fails closed when an allowed command has no sandbox provider/configuration. Denied, unsupported, and approval-required commands are not executed. Empty contracts are incomplete. Docker uses non-root execution, no network, dropped capabilities, no-new-privileges, read-only root, explicit workspace and temporary mounts, CPU/memory/PID limits, bounded stdout/stderr, timeouts, cooperative cancellation, and label-checked cleanup. See [security.md](security.md) for assumptions and operational limits.

The Docker provider is not a complete host security guarantee. It trusts the local CLI/daemon and host kernel. Git worktrees are not sandboxes. The unsandboxed verification helper has been removed from the public path and cannot execute repository commands directly.

## Persistence, ownership, and recovery

`SqliteStorage` initializes versioned SQLx migrations with WAL, foreign keys, and a 10-second busy timeout. Execution intent, its first event, and its initial owner lease are inserted in one transaction. Lifecycle state changes and their events are atomic. `COMPLETED` is accepted only when the latest persisted verification report has a non-empty set of passing checks; the repository transaction checks this and SQLite triggers enforce it for direct state writes. Terminal state updates are also rejected by SQLite. Event sequence allocation serializes through a transaction and a unique `(execution_id, sequence)` index; database triggers reject event updates and deletes. Execution reports are reconstructed from persisted execution, event, workspace, and verification rows. Sensitive-looking JSON field names are rejected; callers must still avoid putting credentials in free-text task descriptions or output content.

Persistent workspaces reserve a database record before invoking `git worktree add`. A local sidecar and the SQLite record hold matching IDs, a random ownership token, canonical paths, and Git administrative/common directory paths. Cleanup checks all three (database, sidecar, and Git registration), then uses the Phase 1 non-forced clean-only removal path. Uncertain or inconsistent metadata refuses cleanup. This is ownership validation, not a sandbox or a defense against a hostile process running as the same OS user.

Every CLI startup first performs read-only inspection of nonterminal executions, their leases, workspace records, and (when Docker is available) matching Synroute-labeled containers. Linux owner identities include a random storage-instance UUID plus PID, process start ticks, and boot ID; PID reuse therefore does not imply the same owner. A recovery transition is applied only after the lease has expired and `/proc` confirms that exact owner process identity is absent. An active owner, a fresh lease, or unknown liveness leaves the lifecycle state and lease untouched. On non-Linux systems or when process identity cannot be read, liveness is unknown and recovery fails closed. SQLite rechecks the owner ID, generation, and expiry inside the recovery transaction before changing state, deleting the lease, appending events, and opening a recovery case.

The default lease is 45 seconds. Owners must call `renew_lease` periodically (recommended every 15 seconds); the API caps requested TTL at 300 seconds. There is no execution coordinator or background heartbeat task yet, so this is a persistence/recovery primitive that future execution code must actively renew. Leases use UTC wall-clock expiry; large system clock changes can delay or accelerate expiry, but the owner-process check is still required before recovery. Recovery never resumes execution or removes workspaces/containers. Uncertain ownership is recorded as an open recovery case without changing lifecycle state. Open cases repeat in startup reports until acknowledged or resolved, and remain queryable afterward. Runtime label matches identify candidates but do not prove historical provenance.

`RecoveryRequired` means liveness or ownership cannot be established automatically and a human must inspect the report before deciding how to proceed. This state is terminal to prevent accidental continuation through normal lifecycle transitions.
